# 0007 — Governed icon and capability-parity exceptions

## Context

Sanitized findings from a publication-blocked, bounded product review showed two gaps in current doctrine. A mature product may preserve one coherent local icon grammar without making that library the portfolio default. Capability maps may also expose legitimate transport boundaries, but weak N/A labels can conceal unfinished adapters and overstate parity.

## Decision

Lucide remains the Norfolk/Kit default. A different product-local library is valid only through a complete approved design-contract exception proving a coherent single-library grammar, accessibility, ownership, compensating controls, bounded migration, approval, and dated review. The exception neither changes the default nor authorizes mixed libraries.

A capability-parity exception is valid only for a physical, legal, or security constraint and must explicitly attest that it is not an implementation gap. It names the human procedure, approval record or class, owner, recovery, reviewer, and review date. Adapter inconvenience, missing wrappers, framework limitations, backlog priority, and unimplemented transports remain gaps.

## Consequences

Design-contract validation rejects undocumented alternate libraries and Lucide aliases that evade canonical stroke rules. Capability-map validation rejects incomplete exceptions, malformed review dates, implementation-gap attestations, and implementation or adapter rationales. Accepted proposal dispositions link to this record.
