# Forbidden design patterns

- Designing or broadly restyling before approved product and IA gates.
- Presenting product/client palette values as universal Norfolk foundations.
- Silent local “improvements,” unrecorded token values, inline escape styles, or erased exceptions.
- A second icon library, mixed stroke weights, decorative icons, emoji interface icons, or icons on homogeneous name lists.
- Stretching focus controls to fill a wide viewport or forcing dense scan work into narrow cards.
- Nested card chrome where hierarchy, spacing, and rules suffice.
- Hover-only meaning, invisible focus, color-only state, or touch targets below 44px.
- Missing loading, error, empty, success, cancel, mobile, keyboard, or reduced-motion behavior.
- Fabricated percentages, fake elapsed time, irreversible optimistic success, or cancellation that only hides the surface.
- Vague errors with no next step, machine nouns, fake certainty, apology filler, or routine cheerleading.
- Treating WorkOS as permission to deliver an unbranded, discontinuous identity journey.
- Promoting a rule from a named but unexamined reference.
- Refreshing a shadcn input without pinned provenance, hashes, file list, and deviation review.
- Replacing a visual baseline without an explicit approve, reject, or defer decision.
- Treating Figma, Replit, H-Analytics, or Kit motion as canonical by filename or recency before lineage reconciliation.
